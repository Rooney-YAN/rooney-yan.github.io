从高中开始，我就很热衷于做笔记，也一直想搭建一套属于自己的知识体系。那时在知乎上看到一种很吸引我的说法：构建笔记体系，就是给自己构筑一个「外脑」。我一下就被这个想法打动了。学过的东西不再随着考试结束散掉，而是能被整理、连接，等到需要时再拿出来用；光是想想都觉得很美好。

我又是一个很极致的完美主义者。面对一份笔记，我很容易继续琢磨它还能不能更完整、结构还能不能更清晰。但做得越久，我越觉得有一个问题始终没解决：**笔记里写着一个概念，是否就意味着我真的理解了它？**

可能只是当时看懂了课件，顺手把定义抄进笔记；也可能我能认出一个术语，却没办法独立解释它，更别说把它用到一道新题里。笔记的完整程度，和我自己的掌握程度，中间似乎还隔着一段距离。我想知道这段距离具体在哪里。

## 从「继续补笔记」到「先问我会不会」

这就是我做 [NoteLoop](https://github.com/Rooney-YAN/NoteLoop) 的起点。我希望把课程材料和自己已有的笔记放在一起看，找出哪些知识点没有写到、哪些写得不够清楚。不过，仅仅比较两份文本还不够。笔记没写，并不能直接证明我不会；笔记写了，也不能证明我会。所以在修改笔记之前，NoteLoop 会先让我答几道题。

目前的流程是这样的：上传课程 PDF，放入自己的 Markdown 或纯文本笔记；系统分别分析材料和笔记，再生成一份知识覆盖情况。随后它给出六道诊断题，包括单选、多选和简答。答题时我还要标出自己的信心程度，因为「答对但靠猜」和「答错却很确信」，显然值得不同的复习方式。

题目本身也可能出错，因此生成后还会经过一次独立审核，检查题意、答案和它是否真的对应课程材料。最后，NoteLoop 根据回答给出诊断，并在有必要时建议一小段 Markdown 补丁。我要不要复制、追加或跳过，由我自己决定；已有笔记不会被悄悄改写。

## 为什么只补一小段

这可能是整个产品里最像我自己的一个决定。既然已经花时间建立了笔记体系，我并不想每次复习都让 AI 把整份笔记重新生成一遍。那样看起来很整齐，却很难分辨哪些内容是我原本写的，哪些是后来补的，也容易把已经想清楚的表达冲掉。

我更希望每一次修改都有理由：哪道题暴露了问题，问题是什么，为什么需要补上这一点。如果只是粗心答错，或者笔记里已经正确覆盖了相关内容，那就不必为了「更完整」再多写几段。对一个习惯追求完整的人来说，学着接受「这里不用改」，反而挺重要的。

## 现在的 NoteLoop

它还是一个浏览器里的 Demo。PDF 的文字会在本地提取，但扫描版 PDF 没有 OCR，图表和图片也不能被可靠理解；模型诊断会受材料质量、题目质量和回答影响。六道题可以帮我发现值得回头看的地方，不能证明我已经掌握了整门课。使用时也需要自己提供模型 API Key，可能产生调用费用。

即便如此，我还是很喜欢这个尝试。以前我常问：「这份笔记还能怎么写得更好？」现在我多了一个更有用的问题：「我究竟在哪一步没有想明白？」NoteLoop 就是我试着回答它的方式。
